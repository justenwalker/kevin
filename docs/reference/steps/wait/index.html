    builtin:wait#

    Blocks a step’s dependents until a check succeeds: a TCP dial, an HTTP(S) probe, a kubectl wait/rollout status, a command retried until it exits zero, or a fixed duration sleep. Useful after a kubectl or helm step applies a manifest, to gate a dependent step on the workload actually being ready. See Deploying workloads.

    A tcp check’s address may be a plain host:port, or the socks5://<relay>/<host:port> form a builtin:kind step’s expose entries publish as a needs.<step>.system.expose_<name> value, to reach a service inside a kind cluster through its relay. system is a sub-namespace kept separate from out (a step’s own outputs); see Cross-step values:

    postgres_ready: {
    uses: "builtin:wait"
    needs: ["cluster", "postgres"]
    with: {
        timeout: "2m"
        tcp: address: "${needs.cluster.system.expose_postgres}"
    }
}
    FieldTypeDefaultDescription
    timeoutstring"60s"The total time to wait for the check to succeed.
    intervalstring"1s"How often to retry the check. It also bounds each individual attempt: a dial, a request, a kubectl call, or a command run.
    tcp#TCP-Dials address until it accepts a connection.
    http#HTTP-Requests url until it returns the expected status.
    kubectl#Kubectl-Runs kubectl wait or kubectl rollout status against an existing cluster.
    exec#Exec-Retries a command until it exits zero.
    durationstring-Sleeps for a fixed amount of time, such as "5s", instead of checking anything. timeout and interval do not apply to it.

    Exactly one of tcp, http, kubectl, exec, duration must be set. Up rejects a with block that sets zero or more than one.

    #TCP#

    FieldTypeDefaultDescription
    addressstring-Required. Host:port to dial, or a "socks5://<relay>/<host:port>" URL, the form a builtin:kind step’s expose entries publish as a "needs.<step>.system.expose_<name>" value, to dial through the kind SOCKS5 relay instead of directly.

    #HTTP#

    FieldTypeDefaultDescription
    urlstring-Required. The address to request, such as "http://${needs.api.out.host_8080}/healthz".
    methodstring"GET"The HTTP method to use.
    statusint200The response status code that counts as ready.

    #Kubectl#

    FieldTypeDefaultDescription
    kubeconfigstring-Required. A path, or a "${...}" expression that reads one from needs, such as "${needs.cluster.out.kubeconfig}".
    contextstring-Selects the kubeconfig context. Defaults to the kubeconfig’s current-context.
    namespacestring-The target namespace.
    resourcestring-Required. The target, such as "pod/mypod" or "deployment/api".
    forstring-The condition to wait for, passed to kubectl wait –for=, such as "condition=Ready".
    rolloutboolfalseRuns kubectl rollout status against resource instead of kubectl wait.

    Exactly one of for, rollout must be set.

    #Exec#

    FieldTypeDefaultDescription
    command[string, ...string]-Required. The argv to run and retry. There is no shell: use ["sh", "-c", "..."] if a shell is needed.

    Kind: probe. A wait step creates no resource to clean up, so it has no Down and does nothing on teardown.

    Idempotent: a wait step creates nothing, so it’s safe to rerun, directly, or swept into a cascading rerun of a step it depends on.
