    kubectl

    builtin:kubectl#

    Idempotent

    Applies a manifest, a manifest directory, or a kustomization to an existing Kubernetes cluster, using the host kubectl binary. See Deploying workloads.

    app: {
    uses: "builtin:kubectl"
    needs: ["cluster"]
    with: {
        kubeconfig: "${needs.cluster.out.kubeconfig}"
        context:    "${needs.cluster.out.context}"
        manifest:   "apiVersion: v1\nkind: Namespace\nmetadata:\n  name: demo\n"
    }
}
    FieldTypeDefaultDescription
    kubeconfigstring-Required. A path, or a "${...}" expression that reads one from needs, such as "${needs.cluster.out.kubeconfig}".
    contextstring-Selects the kubeconfig context. Defaults to the kubeconfig’s current-context.
    namespacestring-The target namespace for a manifest that names none.
    manifeststring-Inline YAML to apply.
    pathstring-A manifest file or directory, applied with -f. Relative to the project directory unless absolute.
    kustomizestring-A kustomization directory, applied with kubectl -k. Relative to the project directory unless absolute.
    server_sideboolfalseApplies with –server-side.
    keepboolfalseLeaves the applied resources in place on Down, instead of deleting them.

    Exactly one of manifest, path, kustomize must be set.
